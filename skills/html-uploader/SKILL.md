# HTML 文档上传（多系统适配器架构）

将本地 HTML 文件上传到目标文档系统。不同系统的差异（能力发现、认证、接口路径、字段名、成功判据）全部封装在**适配器文件**中；本 Skill 主体先执行第 0 段确定"系统地址 + 访问密钥"，再执行统一的上传流程。新增一个目标系统 = 新增一个适配器文件，不修改本文件。

> **统一执行方式**：本技能的所有实际网络请求**只通过 Python 脚本** `scripts/upload_skill.py` 完成，**不使用 curl**。脚本按适配器文件解析接口约定、认证形态、字段映射，并提供 401 自动重登、429 限流等待、密钥/令牌不落盘与日志脱敏。新增系统时复制参考脚本改造其 `Client`/入口即可。

## 输入参数

| 参数 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| 文件路径 | 是 | 无 | 待上传的 .html/.htm 文件（多文件时逐个执行） |
| 系统 | 否 | `htmlview-agent-api` | 适配器名称；未提供且存在多个适配器时列出可选系统询问用户 |
| 基础地址 | 否 | 见第 0 段 | 目标系统的主机与端口；优先级：当次提供 → 环境变量 → `config.json` → 适配器声明；**均缺失时以提问获取** |
| 凭据 | 视适配器 | 无 | API Key / Token 等；**只从环境变量或用户当次输入读取，绝不落盘**；未设置时以提问获取 |
| 标题 / 标签 / 摘要 | 否 | 文件名（去扩展名）/ 无 / 无 | 元数据 |

## 0 配置与凭据获取（前置，必须先于上传流程执行）

规则：**进入任何网络请求前，"系统地址"与"访问密钥"两项都必须已确定；只要有一项未设置，就以提问方式向用户获取**，禁止用示例值、历史值或猜测值硬试。脚本会在缺少必要配置时返回非 0 退出码，并提示先完成预检。

### 0.1 预检（每次任务先跑一次）

```bash
python "<本Skill目录>/scripts/check_config.py" [--system <适配器名>] [--base-url <用户当次给出的地址>] [--key-env <环境变量名>]
```

目标系统未确定时先定系统：用户当次指定 → `config.json` 的 `default_system` → `adapters/` 下只有一个适配器则用它 → 多个适配器则列出供用户选择（与地址、密钥的提问合并为同一轮）。

脚本判定优先级与输出：

- 系统地址：当次参数/用户指令 → 环境变量 `HTMLVIEW_BASE_URL` 或 `<SYSTEM>_BASE_URL` → `config.json` → 适配器 `base_url` 声明
- 访问密钥：适配器 `auth` 段声明的环境变量（如 `HTMLVIEW_KEY`）是否已设置；脚本只报告"是否已设置"，不读取也不回显密钥内容
- 输出 JSON 含 `missing`（缺失项）与 `ask`（可直接发起的提问文案与选项）
- 退出码：`0` 全部就绪 / `3` 有缺失，需提问 / `4` 适配器文件不存在

### 0.2 缺失时提问（多缺失项合并为一轮）

只在预检确认缺失后提问，并把缺失项放在**同一轮提问**中一次问完，避免挤牙膏式追问：

- **系统地址**：选项给 `config.json` 的 `last_base_url`（有则列出）、`http://localhost:8080`（本地部署常见值），并保留"其他"让用户填写真实地址。
- **访问密钥**：选项里**绝不带任何真实密钥值**。选项为：我现在提供（选"其他"直接粘贴）／已写入环境变量 `<ENV_NAME>` 请直接读取／目标系统无需鉴权。
- 用户拒绝提供或给不出 → 终止任务并说明缺什么，不进入上传流程。
- 适配器缺失（退出码 4）→ 先按"新增适配器"处理，再回到本段。

### 0.3 获取后的处理

- **系统地址**：写入 `config.json` 对应系统的 `base_url`，并同步 `last_base_url`，下次免问（地址非敏感，可持久化）。
- **访问密钥**：仅当次任务使用，写入本次进程的环境变量（`$env:HTMLVIEW_KEY='...'` 或 `os.environ['HTMLVIEW_KEY']=...`）供脚本读取；**绝不写入 `config.json`、适配器、脚本或日志**。
- Python 每次以子进程方式运行、环境变量不跨进程保留：若密钥是通过提问获得而非已设环境变量，脚本进程内合适的做法是由本 Skill 以 `env={..., 'HTMLVIEW_KEY': key}` 传入 `subprocess`，或提示用户在 shell 中 export 后重跑。

### 0.4 已配置但鉴权/连通失败

上传中出现 401 `invalid_key`、403 `key_change_required`、连接拒绝等 → 视为地址或密钥失效，**回到 0.2 重新提问获取**（提问时先列出当前值让用户确认或更正），不要反复重试同一组配置。修正后的地址同步更新 `config.json`。

### 0.5 配置文件 `config.json`（非敏感）

```json
{
  "default_system": "htmlview-agent-api",
  "systems": {
    "htmlview-agent-api": { "base_url": "", "key_env": "HTMLVIEW_KEY", "last_base_url": "" }
  }
}
```

只允许写入 `base_url`、`key_env`、`default_system`、`last_base_url` 等非敏感字段。用户要求"把密钥也记住"时明确拒绝并说明原因，可建议其自行把 `export HTMLVIEW_KEY=...` 加进自己的 shell 配置文件——本 Skill 不代写密钥。

## 统一上传流程

按以下步骤执行，全部网络请求走 `scripts/upload_skill.py`。

### 1. 加载适配器

读取 `<本Skill目录>/adapters/<系统名>.md`。适配器文件不存在时，列出 `adapters/` 下全部适配器供用户选择；用户描述了未适配的系统时，按"新增适配器"规范先创建适配器文件再继续。

### 2. 执行上传脚本

```bash
python "<本Skill目录>/scripts/upload_skill.py" \
  --file "<源文件绝对路径>" \
  --system "<适配器名>" \
  [--title "<标题>"] [--tags "<逗号分隔>"] [--summary "<摘要>"] \
  [--base-url "<地址>"] [--insecure]
```

脚本内部顺序：认证（按适配器 `auth` 段，`login-bearer` 先登录换令牌）→ 能力发现（适配器声明 `discovery` 时）→ 上传（multipart 或 JSON）→ 结果判定。行为约定：

- 认证：凭据只从环境变量或 `--key`（不推荐内联）读取；`login-bearer` 形态先 `POST` 登录端点换会话令牌，令牌进程内复用、不落盘；收到 401 自动重登一次；收到 403 `key_change_required` 中止并提示用户先完成改密；登录限流 429 读 `Retry-After` 等待，禁止逐次上传都登录。
- 网络失败：连接拒绝、超时、DNS 解析失败、TLS 证书错误统一转为可操作提示并返回退出码 `3`（视为地址不可用，按 0.4 回到提问环节），不打印原始堆栈。
- 中文编码：元数据与文件名由脚本以 UTF-8 直接编码进 multipart/JSON，无需手工准备 title.txt 等中间文件。
- 输出：脚本打印成功时的系统返回关键信息（id/url、标题等）与阅读地址；失败时打印含错误码/字段的响应片段，用于结果判定。

### 3. 结果判定与清理

脚本退出码语义（据此分流，不要一律当"配置问题"处理）：

| 退出码 | 含义 | 处理 |
|---|---|---|
| `0` | 上传成功 | 报告 id/url、标题、标签与访问地址 |
| `1` | 载荷或服务端错误 | 文件不存在/类型不符、超限，或上传被拒；按适配器 `errors` 段给原因 |
| `3` | 地址或凭据不可用 | 配置缺失，或网络层失败（连接拒绝/超时/DNS/TLS）；按 0.4 回到提问环节 |
| `4` | 适配器文件不存在 | 先按"新增适配器"处理 |

- 失败时读取脚本输出中的错误信息，结合适配器 `errors` 段给出具体原因与修复建议（如 413 超限、400 字段不符等）；不盲目重试。
- 出现鉴权/连通类错误（401/403/连接拒绝）按 0.4 回到提问环节重新获取配置。
- 脚本不落临时文件（密钥/令牌仅内存）；如曾额外产生临时元数据文件应删除。

## 适配器文件规范

路径：`<本Skill目录>/adapters/<系统名>.md`。每个适配器必须包含以下段落（缺失任何一段视为适配器不完整，按失败处理）：

```markdown
# <系统名>

- base_url: 默认基础地址（可为空，空则每次询问）
- max_size: 单文件上限（如 20MB）
- auth: none | bearer:<环境变量名> | login-bearer:<登录端点>:<环境变量名> | header:<名称>:<环境变量名> | basic
- discovery: 能力发现/探活方式（GET 路径与预期返回特征，或 none；login-bearer 先登录再发现）

## auth（可选；login-bearer 等动态认证形态必填）
登录端点、请求/响应字段、令牌有效期与复用、mustChange/改密约束、限流约定。

## request
接口方法、路径、Content-Type 与字段映射：
- file → <字段名/位置>
- title → <字段名>（可选）
- tags → <字段名，含分隔约定>（可选）
- summary → <字段名>（可选）

## success
成功状态码与判定字段（如 201 + 响应含 id）。

## errors
常见错误码 → 原因与修复建议。
```

说明：适配器 `request` 段的字段映射（`- file → \`file\`` 等）、方法、端点、Content-Type、`success` 状态码与判定字段会被 `upload_skill.py` 自动解析，因此适配器内**无需（也不要）写 curl 命令**，只用上面的声明式段落描述接口约定。

## 新增适配器

用户要求接入新系统时：

1. 向用户或该系统的接口文档确认：基础地址、认证方式、上传端点、字段名、成功判据、大小限制。
2. 按上述规范创建适配器文件后，立即用一次真实小文件上传验证（用户同意后）。
3. 验证通过才视为适配完成；失败则修正适配器，不改统一流程。

## 参考实现

`scripts/upload_skill.py`（Python 标准库，零依赖，**不使用 curl**）：统一执行器——解析适配器、按认证形态登录、能力发现、multipart/JSON 上传、结果判定、401 重登、429 限流、密钥/令牌日志脱敏。接入新系统时通常只需新增适配器文件即可复用；确有特殊协议时再复制其 `Client` 类改造。

## 注意事项

- 系统地址可写入 `config.json`（非敏感）以便下次免问；凭据一律不写入任何持久文件，只经环境变量或当次输入使用（见第 0 段）。
- 地址或密钥未设置时必须先提问获取，不得用示例值/历史值硬试；提问时选项内不得出现真实密钥。
- 会话令牌（login-bearer 换取的 token）仅存于进程内存，任务结束即弃；日志与报错信息中不回显密钥与令牌全文。
- 上传前不修改 HTML 内容，只做复制与元数据准备。
- 批量上传共用同一次能力发现结果，逐文件执行上传。
- 适配器文件只写接口约定与占位符（如 `<环境变量名>`），不写真实地址、令牌或用户数据。

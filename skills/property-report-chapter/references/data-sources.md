# 数据来源与合规规范

## 一、允许的数据来源

楼盘公开信息的检索平台（按信息质量排序）：

| 平台 | 适合获取 | 注意 |
|---|---|---|
| 各地住建局 / 房管局官网 | 备案价、预售证、开盘信息 | **最权威**，优先采用 |
| 房天下 | 均价、户型、楼盘详情、开盘动态 | 挂牌价可能高于实际成交 |
| 安居客 | 均价、二手房挂牌、小区配套 | 挂牌价与成交价有差距 |
| 贝壳 / 链家 | 二手房成交参考、小区配套 | 成交参考价相对可靠 |
| 楼盘网 / 吉屋网 / 58爱房 | 楼盘详情、优惠信息 | 营销信息较多，需交叉验证 |
| 网易房产 / 腾讯房产等媒体 | 区域分析、政策解读 | 观点类，需区分事实与评论 |
| 高德 / 百度地图 | 位置、POI、通勤距离 | 需地图 API 或手动核对 |

**交叉验证原则**：同一个关键数字（尤其是价格），至少两个来源一致才写进报告；
只有一个来源时，标注"据 X 显示"并保留不确定性。

## 二、必须写清的口径

| 数字类型 | 必须说明 |
|---|---|
| 价格 | 是备案价、网签均价、挂牌价还是成交价；数据截止月份 |
| 面积 | 建筑面积还是套内面积；得房率的计算基数 |
| 距离 | 直线距离还是导航路程；到哪个具体点位（地铁口、校门） |
| 时间 | 通勤时长是否含步行、是否高峰时段 |
| 学区 | 是"对口"还是"划片范围"；以教育局最新文件为准 |
| 规划 | 是已批复、已开工还是仅规划；注明来源文件与时间 |

## 三、引用的写法

- 正文中出现关键数据时，就地标注来源，例如：（房天下，2026-06）、（市住建局备案信息）。
- 图表 `figcaption` 必须写明数据来源与口径。
- 页脚 `FOOT_DATA_NOTE` 汇总本章全部来源与数据截止日期。

## 四、合规红线

**必须遵守**：

1. **只使用公开渠道信息**。不编造数据，不把推测写成事实；不确定处用区间与条件句。
2. **价格标注"参考均价"**，并提醒"实际以售楼处公示为准"。
3. **必须含免责声明**："本报告仅供参考，不构成购房建议或投资建议。"
4. **不写绝对化承诺**。禁止"必涨""稳赚""包租""保底收益""升值 xx%"等表述。
5. **不评价开发商信誉**（无公开依据时），只陈述可查证的事实（如交付记录、项目数量）。
6. **学区表述必须有依据**，注明"以当年教育局划片文件为准"，不做承诺。
7. **不含任何个人信息**：不采集购房者、业主、销售的个人信息，不引用私人聊天记录。
8. **不引导交易**：不推荐中介、不放返佣链接、不给购房导流。

**不得做的事**：

- 不抓取需登录或付费才能访问的内容。
- 不使用未公开的内部数据、非公开发售信息。
- 不基于网络传言、无法核实的爆料撰写结论。
- 不把竞品描述为负面评价（只做客观参数对比）。

## 五、数据缺失时的处理

| 缺失情形 | 处理方式 |
|---|---|
| 价格查不到 | 不写具体数字，改为"以售楼处公示为准"，或使用同片区区间并标明来源 |
| 户型数据不全 | 只写已确认的户型，注明"部分户型信息未公开" |
| 配套距离无法测 | 用文字描述区位关系（如"临近 XX 路"），不编造公里数 |
| 竞品不足 3 个 | 说明"周边可比项目较少"，缩短对比表而非凑数 |
| 搜索结果相互矛盾 | 并列列出不同来源的数据，标注差异，不擅自取一个当定论 |

## 六、搜索关键词建议

检索时使用具体关键词组合（年份用当前年份，不要写死）：

```
{楼盘名} 备案价 预售证
{楼盘名} 均价 户型 开盘
{楼盘名} 开发商 容积率 绿化率 总户数
{楼盘名} 位置 学区 划片
{楼盘名} 交房时间 物业费
{所在片区} 楼盘对比 房价 {当前年份}
```

优先采信政府官网与官方公示文件，其次为平台数据，最后才是媒体报道与观点。
